# Лабораторная работа 1. Проектирование и реализация реляционной базы данных


## Задание
По выданному варианту предметной области необходимо:
1. Выделить основные сущности, их атрибуты и связи.
2. Спроектировать реляционную модель данных, приведенную к 3НФ.
3. Построить ER-диаграмму с указанием:
  - таблиц и основных атрибутов;
  - первичных и внешних ключей;
  - связей.
4. Реализовать спроектированную БД в PostgreSQL.
5. Заполнить БД тестовыми данными.
6. Продемонстрировать работу ограничений целостности.


## Требования к базе данных
База данных должна содержать:
- не менее 5 содержательных таблиц;
- не менее 2 ограничений `UNIQUE`;
- не менее 3 ограничений `CHECK`;
- не менее одного составного ограничения;
- `NOT NULL` для обязательных атрибутов;

Необходимо использовать подходящие типы данных PostgreSQL. Выбор типов данных, ключей
и правил `ON DELETE` должен соответствовать предметной области.


## Тестовые данные
База должна содержать достаточное количество данных для проверки всех связей и ограничений.

Необходимо подготовить минимум 5 некорректных операций `INSERT`/`UPDATE`,
которые отклоняются PostgreSQL из-за созданных ограничений целостности.


## Изменение требований
После реализации исходной модели преподаватель выдаёт дополнительное изменение
предметной области.

Это отдельная часть задания, которую можно будет сдавать отдельно, после прохождения этого материала.

Необходимо изменить существующую структуру БД с использованием DDL
(`ALTER TABLE`, добавление/изменение ограничений и т.п.).

Пересоздание базы данных не допускается. Существующие данные должны быть сохранены.

## Описание предметной области
Информационная система университета представляет собой базу данных студентов и преподавателей,
структуру образовательной части учебного заведения и реализуемых в нём программ подготовки.

В перспективе развития можно добавить:
- таблицы для формирования учебных планов, так как сейчас система предполагает проведение дисциплин в фиксированное время.
- таблицы занятий в рамках дисциплин для разработки полноценных курсов
- таблицы административной части учебного заведения.

Приведён не полный сценарий расширения системы. Такими темпами можно полностью скопировать базу данных одного из ведущих университетов страны, на что уйдёт много времени.
Поэтому считаю текущую архитектуру достаточной для первой лабораторной работы курса, чтобы полноценно продемонстрировать навыки для выполнения задания.

## Описание основных проектных решений
### 1. Люди
Таблица `person` содержит общие свойства людей, чтобы избежать дублирование свойств.
Таблицы `student` и `teacher` содержат специфические свойства для студентов
и преподавателей соответственно, расширяя таблицу `person` через внешний ключ.

### 2. Здания
Таблицы `building` и `room` содержат свойства зданий и помещений соответственно.
Вторая таблица ссылается на первую для указания принадлежности аудитории к зданию.

### 3. Программы подготовки
Таблицы `faculty`, `department`, `direction`, `program`, `group` содержат свойства
факультетов, кафедр, направлений, программ и групп соответственно в иерархической структуре.

### 4. Дисциплины
Таблица `subject` содержит свойства дисциплин, а таблицы `subject_for_program`
и `subject_for_group` связывает дисциплины и преподавателей
с потоками и отдельными группами по семестрам соответственно.


## Обоснование приведения модели к 3НФ
1. Все свойства атомарны и нет повторяющихся свойств.
2. Все свойства зависят от всех частей составных ключей.
3. Все свойства зависят только от первичных ключей.
